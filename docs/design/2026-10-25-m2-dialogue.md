# M2 设计草案：对话原型（2026-10-25）

对应 README 路线图 M2：「一个场景，实时语音对话，结束后复盘」。
本文是草案，代码最小切片在 `prototype/m2_dialogue/`。M0 对象定义见
[学习者模型](2026-10-22-m0-learner-model.md)，不在这里重复。

## 1. 范围与非目标

做一个竖切：**单场景「向同事解释项目延期」→ 学习者开口（或打字）→ Agent 接话并自然 recast → 结束后出复盘**。

本里程碑不做：

- 多场景选择、场景生成（M0 §5.2 的选取规则依赖 ErrorPattern，属 M3）
- Learner 存储、FSRS、CanDoEvidence 写入、每日计划（M3/M4）
- 音素评测与 P 类 ErrorInstance（实验 D 未通过，沿用 M1 产品边界）
- LLM 实时纠错（事后 LLM 错误检测已可选接入，见 §4；实时链路不存在）
- 学习者录音入库；批处理关闭时音频不上传，启用时也只进系统临时目录、复盘后删除

## 2. 切片架构（现在）

```text
浏览器页面
  学习者输入：Chromium 语音识别（可失败则打字）；Agent 声音：speechSynthesis
      │ 文本
      ▼
prototype/m2_dialogue（标准库本地服务，只监听 127.0.0.1）
  会话状态机（内存，不落盘）
  tutor 后端二选一：
    mock       默认。规则脚本，离线可跑可测，验证交互与复盘数据流
    anthropic  可选。HEARSAY_LLM=anthropic + HEARSAY_ANTHROPIC_API_KEY，Claude 做导师
  recast 规则扫描（学习者文本 → provisional 提示）
  复盘生成（指标 + 目标覆盖 + recast 清单 + summary_zh）
  事后批处理（可选，HEARSAY_M2_BATCH=whisperx）：
    逐轮录音（MediaRecorder，临时目录，复盘后删除）
    → whisperX verbatim 权威转写（实验 A 配置）
    → provisional 核对：confirmed / discarded / 误报率 / 计时
```

明确：**这不是 pipecat 实时流水线**。浏览器语音识别会归一化文本，不能当权威转写；
它只用于驱动对话，与 M0 §4.1 实时链路的地位一致。权威转写仍属事后批处理。

## 3. 与 M0 的对齐

- 场景用 M0 §2.8 `Scenario` 的字段：`agent_role` / `learner_role` / `objectives` /
  `scripted_events`（本场景在约第 2 轮插入 `unexpected_question`：客户临时要一页摘要）。
- 会话类型 `converse`。复盘对应 `Session.metrics` + `summary_zh`。
- recast 提示是 **`status: provisional` 的候选**，不是已确认错误：
  切片以 `recasts` 字段展示，`detected_by: rule`（mock 规则扫描，是
  `asr_llm_realtime` 链路的占位），接口层仍强制 `error_instances: []`。
- 统计口径预留：M0 规定 ErrorPattern 只读 confirmed。切片里 confirmed 只出现在
  批处理复盘的展示中，不写 ErrorPattern / Learner，不计入任何趋势。

## 4. 下一步（切片之后）

1. **实时语音链路**：`realtime.py` 已按 pipecat 官方示例写好（transport → Silero VAD
   → faster-whisper → Claude → Piper TTS），但依赖与模型未装，**未实测**；
   LLM 实时 recast 的结构化抽取也还没做。装好后验证延迟、打断与转写质量。
2. ~~事后批处理~~ **已落地（可选）**：逐轮录音 → whisperX verbatim 转写（实验 A 配置）
   → 按「同一话语 + 同一代码」把 provisional 合并为 confirmed 或标 discarded，
   复盘给出误报率与 `batch.duration_sec`。**LLM 事后错误检测已接**：
   有 `HEARSAY_ANTHROPIC_API_KEY` 时默认用 Claude（`detected_by=asr_llm`），
   输出逐条校验（只收 G/L/I、observed 必须在原文、confidence ≥ 0.6），
   失败回退规则扫描；`HEARSAY_M2_DETECT=llm/rule` 可强制。
   还没做的是用 5 分钟真实对话验证延迟与检测质量。
3. 三个未验证风险（M0 §6 / 状态清单 §2）的测量脚本已放在
   `experiments/exp_e_dialogue/`（**均未实测**，2026-10-25：本机无 API key、
   网络过慢装不起模型）：
   - 实时 recast 误报率：`aggregate.py`，20 段对话 provisional 被 discarded 比例 ≤ 20%
     （现在只能测规则口径；LLM 实时链路误报率待结构化抽取）
   - 会话后批处理 < 60 秒：`batch_latency.py`（5 分钟对话，计时已含模型加载分列）
   - LLM 判 can-do 一致性：`can_do_consistency.py`，同一转写判 5 次，一致率 ≥ 80%
     （通过前不写 CanDoEvidence）

## 5. 切片验收

1. 本地一条命令启动，离线 mock 下完整走完「开场 → ≥4 轮对话 → 意外问题 → 结束复盘」。
2. 可选 Claude 后端：有 API key 时同一页面切换，不需要改前端。
3. 复盘包含：轮次与学习者输出量（词数、占比）、objectives 覆盖情况、
   provisional recast 清单（observed/expected/代码）、中文小结。
4. 全程不写学习者模型、不写音素字段；confirmed 实例只在批处理复盘中展示，
   不进入任何统计。密钥只从环境变量读，不出现在日志和响应里。
5. 批处理启用时：录音只在系统临时目录、复盘后删除；权威转写用 verbatim 配置，
   核对产出 confirmed / discarded / 误报率 / 计时。
6. 单元测试覆盖状态机、recast 规则、复盘指标、批处理核对与接口；
   CI 保持轻量，不调外部 API、不加载模型。
