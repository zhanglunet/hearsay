# M1 真人录音复测：采集规范（组织方）

> 对应议题：[zhanglunet/hearsay#4](https://github.com/zhanglunet/hearsay/issues/4)  
> 设计依据：[docs/design/2026-10-23-m1-risk-validation.md](../design/2026-10-23-m1-risk-validation.md) §2.6、§3.5、§4.4  
> 版本：草稿 2026-10-23 · 路径：`docs/ops/m1-recording-protocol.md`  
> 配套：[docs/ops/m1-consent.md](./m1-consent.md)（录音者知情同意书）

本规范给 **组织采集与复测的人** 用，不面向录音者。录音者只读同意书。

---

## 0. 原则（先读）

1. **先同意，后开录。** 每人签署（或电子确认）`m1-consent.md` 后，再分配匿名编号并开始录音。
2. **学习者录音属个人数据。** 默认：**音频不入库**（不 `git add`、不推到公开 GitHub）；公开仓库只交 **去标识结果 CSV / 汇总与报告**。若要破例入库音频，必须有录音者对「音频入库」的 **另行书面同意**，并在 PR 说明中写明范围。
3. **同意书纸质/电子原件与音频** 与公开仓库隔离存放；仓库内可放本规范与同意书 **模板**，但 **已填姓名的签署件不要提交**。
4. 复测目标不是「录得越漂亮越好」，而是覆盖真实停顿、重复、自我修正与吐字含糊；在可懂的前提下 **不要过度要求重录到完美**。

---

## 1. 人选与规模

| 项 | 要求 |
|---|---|
| 人数 | **≥ 3 人**（建议 3–5，便于看人与人之间差异） |
| 母语 | 中文母语者 |
| 英语水平 | 覆盖 **A2–B2**（自报即可；尽量不要 3 人全是同一档） |
| 年龄 | **≥ 18 岁**（同意书已写明） |
| 排除 | 未签署同意书者；明显无法完成英文朗读且无法在协助下完成者（可另约） |

登记表（本地保存，勿提交公开仓）建议字段：

`speaker_id, level_self, consent_date, consent_form_version, notes`

其中 `speaker_id` 形如 `S01`、`S02`，**不要**用真名做目录名。

---

## 2. 设备与音频格式

对齐报告 §3.5 录音要求与实验 A 既有 wav 设定：

| 项 | 要求 |
|---|---|
| 采样率 | **≥ 16 kHz**（推荐直接 **16 kHz** 单声道，与现有 `exp_a_grammar` wav 一致） |
| 位深 / 格式 | 16-bit PCM **WAV**（或无损录完再统一转 16 kHz mono WAV） |
| 设备 | 笔记本/手机质量良好的麦克风即可；头戴式更稳。**禁止**先经电话带宽（约 8 kHz）压缩再回传 |
| 输入增益 | 峰值大约 -12 dBFS～-6 dBFS，避免削波；也不要过小导致 SNR 很差 |
| 禁止 | 通话录音、语音留言压缩格式作为主交付；重度降噪插件把辅音削掉 |

手机录制时：飞行模式或勿扰，关闭消息提示音；用「语音备忘录 / 录音机」导出 WAV 或 m4a 后 **本地转码** 为 16 kHz mono WAV。

示例（组织方本机，按实际路径改）：

```bash
ffmpeg -i input.m4a -ac 1 -ar 16000 -sample_fmt s16 S01_A_01.wav
```

## 3. 环境

| 项 | 要求 |
|---|---|
| 噪声 | 安静室内；电视/音乐关闭；尽量无他人大声说话 |
| SNR | 主观上语句清晰。若听感嘈杂或脚本侧将提示低 SNR：**换环境重录**，不要把明显低 SNR 条目标进正式集（与 §3.5「检测到低 SNR 时提示换环境」一致） |
| 回声 | 避免空旷卫生间式回声；普通房间即可 |
| 隐私 | 不要录进第三人姓名、地址等无关隐私内容；开录前确认房内只有知情参与者 |

## 4. 朗读材料与话术

### 4.1 实验 A（必做）：24 句

- 材料：仓库内 `experiments/exp_a_grammar/sentences.json`
- 共 **24 句**，含植入语法错误（字段 `text` 为朗读稿；`errors` / `codes` 供事后判定，**不要念给录音者听「正确说法」**）。
- **话术（必须说清）**：  
  > 「这些句子里有的英文故意写错了。请 **照着读，不要改成你觉得对的说法**。读错稿子上的词反而会破坏实验。」
- 每句读完可短暂停；允许一句内自然换气。若某句严重卡壳，可整句重录 **一条** 替换，保留最终选用的那条即可。
- 建议顺序：按 `id` 1→24；文件命名见第 6 节。

`sentences.json` 字段说明（组织方）：

| 字段 | 含义 |
|---|---|
| `id` | 句号 1–24 |
| `text` | 朗读原文（含错误形式） |
| `codes` | 错误清单代码（如 G02、G10） |
| `errors` | `[错误形式, 纠正形式]` 对，用于事后判定 retained / corrected |

### 4.2 跟读 / 切句（必做）：shadow 句

- 材料：`experiments/exp_c_timestamps/sentences.txt`（多句日常口语，每行一句）。
- 每人至少选 **10 句**（建议 10–20；可固定同一批句以便跨说话人对比，也可按水平略调）。
- 模拟 shadow 块：可屏幕展示一句读一句；允许停顿与轻微自我修正（这正是合成音缺少的现象）。
- **不要**要求录音者先听 TTS 再影子跟读到完全对齐（除非你们明确加「有参考音」子条件）；默认「看稿朗读」即可支撑「原文首末词 ↔ whisperX 词时间戳」评估。

### 4.3 场记

每场本地记：`speaker_id`、日期（Asia/Shanghai）、设备型号、采样率、环境一句话、选用的 C 句行号列表、有无整句重录。

## 5. 切句人工标注（Praat 等）

报告 §4.4：学习者侧应用 **原文首末词匹配 whisperX 词级时间戳** 定句边界；真人场景下没有 Kokoro 真值，故需 **人工标注一部分句边界** 作参照。

| 项 | 要求 |
|---|---|
| 工具 | 推荐 [Praat](https://www.fon.hum.uva.nl/praat/)；也可用 Audacity 标签轨，最终导出可机读时间戳 |
| 标注对象 | 至少覆盖：每名说话人 shadow 材料中的 **全部选用句**，或明确抽样（若抽样，报告里写清比例与抽法） |
| 标什么 | 每句 **句首时间**、**句尾时间**（秒，相对该条 wav 起点）。句首：首词浊音/摩擦起始可辨处；句尾：末词声学结束（可含极短气流，但不要把句间长沉默算进上一句） |
| 导出 | 例如 TextGrid 或 `tmin,tmax,text` CSV；`text` 用句号或 `sentences.txt` 行号 |
| 评估 | 将人工句边界与「原文首末词 → whisperX `word_segments`」得到的边界比误差；阈值沿用 issue：**误差 &lt; 150 ms 的比例 ≥ 90%**（报告中写达到 / 未达到与数字） |
| 谁标 | 组织方或受托标注者；标注指南保持本节能复现即可 |

实验 A 的 24 句若 **一句一条 wav**，句边界可用文件起止近似，切句评估以 shadow 段为主。若 A 也是多句连录，则 A 同样需要按句标注或先按句切分再入库本地目录。

## 6. 文件命名与本地目录

建议本地根目录（**在 `.gitignore` 之外的私有路径**，或仓库内已忽略目录）：

```text
m1_human_audio/                 # 勿提交公开仓
  consents/                     # 签署件扫描/邮件导出；勿提交
  manifests/
    speakers.csv                # 匿名登记；勿提交含真名版本
  audio/
    S01/
      A_01.wav … A_24.wav       # 实验 A，与 sentences.json id 对应
      C_03.wav C_07.wav …       # shadow；数字为 sentences.txt 行号（1-based）
    S02/
      …
  annot/
    S01_C_boundaries.csv        # 或 TextGrid
  README_LOCAL.md               # 仅本地：路径说明、转码命令
```

命名约定：

- `Sxx`：同意书上分配的匿名编号；
- `A_rr`：`rr` 为 `sentences.json` 的 `id`，两位数字；
- `C_ll`：`ll` 为 `sentences.txt` 行号，两位或三位均可，全场统一；
- 不要在文件名中写姓名、手机号。

公开仓库侧（可提交）示例：

```text
experiments/exp_a_grammar/results_human.csv
experiments/exp_c_timestamps/results_human_boundaries.csv
docs/design/…-m1-human-rerecording.md   # 复测报告
```

## 7. 本地存放与 Git 红线

**不要做：**

- `git add` 任何真人 `wav` / `mp3` / `m4a` / TextGrid 原文件（除非有另行书面同意且 PR 已说明）；
- 把含真名的同意书、花名册推进公开远程；
- 在 issue / PR 正文粘贴可还原身份的联系方式与音频外链（可写「音频仅本地，联系组织方」）。

**建议做：**

- 在仓库 `.gitignore` 增加类似规则（若尚未有）：`m1_human_audio/`、`**/consents/`、`*.wav` 下若与实验合成音冲突，则改为更精确路径忽略真人目录；
- 合成音（macOS `say` / Kokoro）与真人音目录分开，避免误删或误提交；
- 备份：加密磁盘或私有网盘；备份同样视为个人数据，适用同一删除期限（见同意书 §3.3）。

## 8. 复测流程（录音之后）

1. **实验 A 复测**  
   - 将真人 wav 接到现有 `experiments/exp_a_grammar/run.py` 的 4 个配置（与合成音同一套判定）：  
     `python exp_a_grammar/run.py --audio-root /path/m1_human_audio/audio --out results_human.csv`  
     （真人 CSV 的 `voice` 列是匿名说话人编号 `Sxx`；旧调用方式不变，仍跑合成音。）  
   - 用 `python exp_a_grammar/report_human.py` 生成 **真人 vs 合成** 保留率对比表（含 ≥80% 达标判定、说话人 × 配置表、verbatim prompt 增益）。  
   - 确认 verbatim prompt 在真人上是否仍明显优于默认配置。

2. **切句复测**  
   - `python exp_c_timestamps/retest_human.py --audio-root /path/m1_human_audio/audio --annot /path/m1_human_audio/annot`：whisperX 转写 + align 取 `word_segments`，用原文首末词匹配得到假设句边界，与 Praat 导出的人工边界 CSV（列：`clip,tmin,tmax,line`）比误差；  
   - 产出 `results_human_boundaries.csv` 与 `results_human.json`，含 < 150 ms 比例、≥ 90% 是否达标与首末词未匹配句数。

3. **报告**  
   - 每个阈值写「达到 / 未达到」和数字；  
   - 对设计文档 **4.1**（低归一化、verbatim prompt）与 **5.3**（shadow 切句）给出建议（只写报告，是否改 M0 正文另议）。

4. **PR 交付物**  
   - 脚本改动（若有）；  
   - **结果 CSV / JSON 与报告**；  
   - **默认不包含音频**。  
   - PR 描述中写明：已收集同意书、音频仅本地、说话人匿名编号规则。

环境注意（issue #4）：torch / torchaudio 钉 `2.8.0`；whisperX 需脚本内已有的 `torch.load` 垫片；CPU 上 large-v3 约 14 s/条。

## 9. 检查清单（开录前 / 提交 PR 前）

**开录前**

- [ ] 同意书版本号已填进场记；联系人占位已换成真人
- [ ] 每名说话人已签署；已分配 `Sxx`
- [ ] 设备确认 ≥ 16 kHz、单声道方案明确
- [ ] 已向说话人说明「照读错误句、不要纠正」

**本地收工**

- [ ] 每名说话人 A 组 24 条齐；C 组句数 ≥ 10 且行号有清单
- [ ] 抽查无削波、无电话音质
- [ ] 句边界标注文件与音频 ID 能对上

**开 PR 前**

- [ ] `git status` 无真人音频、无同意书签署件
- [ ] 结果表无姓名、邮箱、人脸等
- [ ] 报告含对比表与阈值结论
- [ ] issue #4 在 PR 正文用 `Closes #4` / `Refs #4`（若本 PR 只交规范未跑完实验，用 `Refs`）

## 10. 与同意书的分工

| 文档 | 读者 | 内容 |
|---|---|---|
| `m1-consent.md` | 录音者 | 目的、录什么、使用/保存/删除、默认不入库音频、撤回、联系人 |
| 本文件 | 组织方 | 人数与水平、设备、环境、材料、标注、命名、Git 红线、交付物 |

冲突时以 **更保护录音者** 的条款为准，并先修订同意书再继续采集。
