# PRD-493/T1：hearsay 陪练技能评估设计草稿

> 状态：设计草稿（T1），只设计不写代码；对应 trend issue：zhanglunet/trend#2385
> 来源：PRD-493《hearsay 陪练技能评估》；统一主题：技能要验收
> 日期：2026-11-17

## 1. 背景与目标

hearsay 的陪练技能包越写越多，但没有一套东西定期回答“这些技能还管用吗”：技能会过期（上游变了）、会重叠（两个技能教同一件事）、会失效（agent 根本不按技能走）。

本设计给技能包配一套评估：质量门 → 语义重叠检测 → 合成评测集 → 实测，四件套跑完，评估结果落账；过期 / 重叠 / 失效的技能进整改清单，不直接删。

目标一句话：陪练技能包定期体检，坏技能进清单修，学员只收到评估过关的技能出的纠正。

## 2. 四件套设计

### 2.1 质量门：技能是否真让 agent 少纠错

- **判定口径**：质量门量的是“技能是否改变 agent 行为”，不是“技能文档写得好不好”。对照实验：同一批陪练任务，有技能 vs 无技能（或旧版技能）跑两遍，比较纠错行为。
- **核心指标**（初版阈值，T1 评审定、实测后复核）：
  - 误纠率：错误纠正 / 全部纠正，目标相对无技能基线下降 ≥ 20%，且绝对误纠率 ≤ 5%。
  - 漏纠率：应纠未纠 / 应纠总数，相对基线不恶化（上升 ≤ 2 个百分点）。
  - 技能触发率：任务中技能被实际引用 / 触发的比例；触发率 < 10% 的技能判“疑似失效”，进复核而非直接判死。
- **判定规则**：三项指标全部达标为“过关”；任一项不达标为“未过关”，进整改清单；连续两次评估未过关，升级为“重点整改”，仍不直接删。
- **阈值来源**：阈值由 T1 设计评审定初值，T2 实测跑完首份报告后复核一次，阈值调整要留变更记录（旧值、新值、理由）。

### 2.2 语义重叠检测：陪练技能之间别重复

- **方法**：技能两两比对，文本相似度（技能描述 + 触发条件 + 示例）与语义相似度（embedding 余弦）双通道；任一通道超过阈值即进入人工复核队列。
  - 文本相似度阈值（初值）：Jaccard / TF-IDF 余弦 ≥ 0.70 疑似重叠。
  - 语义相似度阈值（初值）：embedding 余弦 ≥ 0.85 疑似重叠。
- **判定口径**：机器只给“疑似重叠”候选对并附证据（重叠片段、相似度分值）；是否真重叠、合并还是保留，由人工在评审里定。机器不自动合并、不自动删。
- **输出**：重叠候选清单（技能 A、技能 B、相似度、重叠证据），随评估报告一起落账。

### 2.3 合成评测集：造陪练题考技能，题源自真实纠正案例

- **题源**：全部评测题必须源自真实纠正案例（脱敏后的学员纠错记录、复盘会话案例）。无来源的题不进评测集；每道题挂证据来源（案例编号、原始场景摘要、脱敏说明）。
- **题型**：误纠识别题（给一段学员表达 + agent 的纠正，判断纠正对错）、漏纠题（给一段应纠未纠的表达，判断是否应纠、怎么纠）、边界题（易误纠的近义 / 语用场景）。
- **证据要求**：每道题 = 题干 + 标准答案 + 判定依据（引用的技能条款）+ 来源案例；答案有争议的题先标“待裁决”，不计分。
- **规模与更新**：首版评测集不少于 50 题，覆盖主要陪练技能；每轮评估前复核题库，过期题（上游规则已变）标记过期、下架，不删除历史记录。

### 2.4 实测：跑真实陪练任务量行为变化

- **方案**：取真实陪练任务样本（脱敏），有技能版 agent 与无技能基线版 agent 各跑一遍；样本量首版不少于 30 个任务，覆盖主要技能。
- **行为变化度量**：误纠率、漏纠率、纠正采纳率（学员接受纠正的比例）、任务完成度四项，与基线对比；只报“有技能是否让行为变好”，不评价 agent 干活的过程。
- **可复核**：实测记录任务 ID、技能版本、输入输出摘要、评分结果，结论可按记录复核；抽样复核比例 ≥ 10%。

## 3. 落账与整改清单

- **评估报告**：每轮评估产出一份报告（技能清单、各项得分、过关 / 未过关、重叠候选、评测集版本），落账存档，报告带版本号与评估日期。
- **整改清单**：append-only（只追加、不改写历史）；每条记录技能、问题类型（过期 / 重叠 / 失效）、证据、整改期限、状态（待整改 / 已整改 / 已复核）。
- **闸门**：评估未过关的技能不得进入下游（T3 落地）；评估结论只进整改清单，技能下线另走审批，绝不直接删。

## 5. 红线

- 只借鉴思路，不复用代码（借鉴对象：NVIDIA/SkillEvaluator Apache-2.0、elementalsouls/Claude-BugHunter MIT、google-labs-code/stitch-skills Apache-2.0，均只借鉴思路）。
- 评估结果只进整改清单，不直接删技能；技能下线另走审批。
- 评测题必须有真实案例证据来源，无来源的题不进评测集。
- 不审产物、不审 agent 干活过程、不改技能包形态与上架流程。
- 实现类 PR 只开不合并，等用户 review。
